# Git 协作指南

给两个人的小团队用。看完这一篇就够了。

---

## 一、最重要的规则（先看这条）

> ### 🔴 同一时间，只能有一个人修改同一个场景（`.scene`）或预制体（`.prefab`）

**原因**：Cocos 的 `.scene` / `.prefab` 文件是 JSON，但里面用 `{"__id__": 数字}` 互相引用节点，**数字是数组下标**。两个人同时改同一个场景，Git 合并出来的文件引用会全部错位，场景直接损坏，且**很难修复**。

**做法**：

- 开工前在群里说一句「我要改 `main.scene`」
- 改完提交推送，再说一句「改完了」
- 另一个人的改动如果落在别的场景/预制体上，不会有任何冲突

代码文件（`.ts`）随便改，Git 能自动合并。

## 二、日常流程（每天照做）

### 开工前：先拉取

```bash
git pull
```

**这一步不能省。** 不拉取就开始改，最后推送时必然冲突。

### 工作中：小步提交

改一小块就提交一次，别攒一整天。

```bash
git status              # 看看改了哪些文件
git add -A              # 把所有改动放入暂存区
git commit -m "加上萝卜的播种逻辑"
git push                # 推送到 GitHub
```

**提交信息怎么写**：说清楚"做了什么"，不要写"更新"、"修改"、"fix"。

- ✅ `加上萝卜的播种逻辑`
- ✅ `修正离线收益计算多算一小时的问题`
- ❌ `更新`
- ❌ `改了一下`

### 收工前：一定要推送

```bash
git push
```

**只 commit 不 push，改动只在你自己的电脑上，队友看不到。**

### 一句话版本

```bash
git pull && git add -A && git commit -m "说明你改了什么" && git push
```

## 三、Cocos 项目特有的注意事项

### ✅ 必须提交的

| 文件 | 为什么 |
|---|---|
| `assets/**` 里的所有东西 | 游戏内容本体 |
| **`assets/**/*.meta`** | ⚠️ **极其重要**，见下 |
| `settings/` | 工程设置（构建配置、引擎模块） |
| `package.json` / `tsconfig.json` | 工程定义 |

### ⚠️ 关于 `.meta` 文件（新手最容易搞错的地方）

Cocos 里**每一个资源**（场景、脚本、图片、音效）旁边都有一个同名的 `.meta` 文件，比如：

```
assets/scenes/main.scene
assets/scenes/main.scene.meta    ← 这个
```

`.meta` 里存着这个资源的 **UUID**。场景里引用一张图片，引用的不是路径，而是**图片的 UUID**。

**所以**：

- ❌ **绝对不能**删 `.meta` 文件，也不能把它加进 `.gitignore`
- ❌ **绝对不能**手动编辑 `.meta` 里的 uuid
- ❌ 删除资源时，要**连 `.meta` 一起删**（在 Cocos 编辑器里删，不要用资源管理器删）

如果 `.meta` 丢了，Cocos 会重新生成一个**新的 UUID**，所有引用这张图的地方全部变成"丢失资源"。

### ❌ 不提交的（`.gitignore` 已配好，不用管）

| 目录 | 是什么 |
|---|---|
| `library/` | 引擎导入缓存，几万个文件，但可以随时重建 |
| `temp/` | 编译临时文件 |
| `build/` | 构建产物 |
| `profiles/` | 个人偏好设置（窗口布局等） |
| `node_modules/` | npm 依赖 |

**克隆下来后第一次打开会比较慢**，因为 Cocos 要重新生成 `library/`，这是正常的。

### 🔴 版本必须一致

两个人都必须用**完全相同**的 Cocos Creator 版本（当前 **3.8.8**）。

版本不同会重写 `.meta` 和场景格式，产生海量无意义冲突。升级版本前**必须先商量**。

## 四、出了冲突怎么办

### 情况 1：`.ts` 代码冲突（好解决）

```bash
git pull
# 提示 CONFLICT，打开冲突的文件，会看到：
#   <<<<<<< HEAD
#   你的代码
#   =======
#   队友的代码
#   >>>>>>> origin/main
```

手动改成你想要的样子，删掉 `<<<<<<<` `=======` `>>>>>>>` 这三行标记，然后：

```bash
git add -A
git commit -m "解决冲突"
git push
```

### 情况 2：`.scene` / `.prefab` 冲突（麻烦）

**不要试图手动合并**（几千行 JSON，`__id__` 全错位）。

**正确做法**：

```bash
# 1. 放弃你本地对这个场景的修改
git checkout --ours assets/scenes/main.scene
#    （或者 --theirs 保留队友的）

# 2. 重新在 Cocos 编辑器里把你的改动再做一遍
```

**所以**：这条路的代价很高，请回到第一节的规则——**约定好谁改哪个场景**。

### 情况 3：改乱了想全部推翻重来

```bash
git reset --hard HEAD        # 丢弃所有未提交的修改
git clean -fd                # 删除所有新增的未跟踪文件（小心！）
```

> `git clean -fd` 会删除未提交的新文件，**不可恢复**。执行前先 `git clean -nd` 预览一下会删什么。

## 五、常用命令速查

| 我想…… | 命令 |
|---|---|
| 看改了哪些文件 | `git status` |
| 看具体改了什么内容 | `git diff` |
| 拉取队友的改动 | `git pull` |
| 提交所有改动 | `git add -A && git commit -m "说明"` |
| 推送 | `git push` |
| 看提交历史 | `git log --oneline -20` |
| 看远程仓库地址 | `git remote -v` |
| 撤销某个文件的未提交修改 | `git checkout -- <文件路径>` |
| 撤销最近一次提交（保留改动） | `git reset --soft HEAD~1` |

## 六、大文件提醒

GitHub 有硬性限制：

- **单个文件超过 100 MB 会被拒绝**
- 超过 50 MB 会警告

对 2D 小游戏来说，正常的美术资源不会超。但如果以后要加**背景音乐、大量高清图**，单个文件可能变大。

**真遇到了再处理**，方案是 Git LFS（大文件存储）：

```bash
git lfs install
git lfs track "*.psd"
git lfs track "*.wav"
git add .gitattributes
```

> ⚠️ 一旦用了 LFS，队友也必须装 `git lfs`，否则拉下来的是一堆指针文件而不是真资源。**启用前先在群里说一声。**

## 七、第一次配置（每台电脑只做一次）

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

邮箱建议用 GitHub 账号绑定的邮箱。

---

## 八、被邀请为协作者后怎么加入

1. 打开仓库地址，点右上角 **Fork 旁边的 ⭐ Star**（可选）
2. 复制仓库地址（绿色 **Code** 按钮 → HTTPS）
3. 本地找个目录：

```bash
git clone https://github.com/<用户名>/<仓库名>.git
```

4. 第一次 `git push` 时会弹出浏览器窗口让你登录 GitHub，登录一次以后就不用再登了
5. 用 Cocos Creator 打开克隆下来的目录（首次会重建 `library/`，等几分钟）
